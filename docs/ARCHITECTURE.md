# Архитектура Survey QA

## Поток проверки

```text
DOCX -> Word parser -> SurveySpec
                           |
URL  -> Platform adapter -> ObservedSurvey
                           |
                    Comparator
                           |
                    Test planner
                           |
                    Browser runner
                           |
                    ComparisonReport
```

## SurveySpec

Все оформления Word приводятся к общей структуре:

- вопрос и его код;
- тип ответа;
- варианты и коды;
- обязательность;
- исключающие и закреплённые варианты;
- ротация;
- условия показа;
- инструкции и предупреждения.

ИИ в будущей версии следует подключать только после детерминированного извлечения DOCX. Ему передаются отдельные неоднозначные инструкции, а не документ целиком. Это снижает стоимость, расход токенов и риск потери структуры таблиц.

## Платформенные модули

Общий интерфейс находится в `app/platforms/base.py`:

- `supports(url)` определяет платформу;
- `discover(url)` получает фактическую структуру;
- `run_scenario(...)` выполняет один маршрут.

Новая платформа не требует менять Word-парсер, сравнение или формат отчёта.

## EnjoySurvey

Модуль использует признаки, доступные в тестовой ссылке:

- `.question-container[data-question-id]`;
- классы `type_multi`, `type_group` и другие;
- `data-value-code` у вариантов;
- класс `exclusive`;
- список `#fastMoveSelect`.

Быстрый переход используется только для инвентаризации. Адаптер ждёт его асинхронное появление на новой версии `n.enjoysurvey.com`, сохраняет порядок пунктов независимо от текущего debug-экрана и учитывает двухфазную перерисовку SPA. Логика проверяется отдельными последовательными прохождениями с чистой браузерной сессией.

## SurveyStudio

Модуль использует тестовый список перехода, атрибуты `data-testid` / `data-question-number` и данные тестовой сессии. Полный список нужен для инвентаризации, а отдельные последовательные сессии — для проверки ветвлений. Суффиксы продукта в кодах (`.195`, `.349`) отделяются от кода вопроса, но повторный несвязанный вопрос с тем же кодом выявляется по формулировке. Если закрытая ветка не раскрывает варианты через тестовую навигацию, вопрос всё равно учитывается по формулировке, но сравнение его вариантов откладывается до фактического прохождения этой ветки.

Перед выполнением сценариев коды ответов Word сопоставляются с фактическими кодами платформы по текстам вариантов. Поэтому разные номера кодов не мешают открыть правильную ветку и сами по себе не считаются ошибкой.

## Безопасность

- разрешены только публичные HTTP/HTTPS URL;
- localhost, private IP и link-local адреса запрещены;
- размер Word ограничен;
- временный файл удаляется после задания;
- одновременность Chromium ограничивается семафором;
- доступ может быть закрыт HTTP Basic паролем.

## Масштабирование

MVP запускает фоновые задания внутри одного web service. Для небольшой исследовательской команды это упрощает развёртывание.

Когда появится параллельная нагрузка, задания следует вынести в отдельный worker, а DOCX временно хранить в закрытом объектном хранилище. Формат `SurveySpec` и платформенные модули менять не потребуется.
